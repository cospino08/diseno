# CP-07: Paciente reserva una franja pasada

| Campo | Valor |
| --- | --- |
| Caso | CP-07 |
| Tipo | Regla de negocio |

| Caso de uso | CU-04 |

## Precondiciones

- `paciente1@demo.test` con perfil completo.
- Existe una franja de ayer (o una de hoy cuya hora ya pasó).

## Datos usados

| Dato | Valor |
| --- | --- |
| Fecha en el buscador | ayer |
| Respuesta simulada de `reservar_cita` | `{ code: 'P0001', message: 'FRANJA_PASADA' }` |

## Pasos

1. En **Buscar**, escribir la fecha de ayer y pulsar **Buscar**.
2. Abrir una confirmación y simular que, al confirmar, la franja ya empezó (la base responde `FRANJA_PASADA`).
3. Desde la consola (ejecución 2), llamar `reservar_cita` con el id de una franja pasada.

Código de consola:

```js
// Con la sesión de paciente1 iniciada, en cualquier página del sitio:
const { supabase } = await import('./assets/js/datos/cliente.js');  // ajustar la ruta relativa
const { data, error } = await supabase.rpc('reservar_cita', { p_schedule_id: <id de franja pasada> });
console.log(data, error?.message);   // esperado: null 'FRANJA_PASADA'
```

## Resultado esperado

`FRANJA_PASADA`; no se crea cita.

## Observaciones

- **Qué prueba la ejecución 1.** Las páginas corren sin cambios, pero las respuestas de
  Supabase se reemplazan, con Chrome DevTools Protocol (`Fetch.requestPaused`), por
  respuestas con el formato exacto del contrato v1.1 (mismas columnas y mismos códigos de
  error en `message`). Así se prueba **la interfaz**: qué muestra, a dónde lleva y qué le
  pide a la base. **No** prueba la base: esa parte la cubren las pruebas de P2
  (`sql/pruebas_seguridad.sql`, 62/62 en Supabase) y la ejecución 2. El script de prueba
  usa Node y por eso **no** está en el repositorio (el proyecto no usa Node); el método
  está descrito en `docs/bitacora_ia.md`.
- Los agentes no tienen las contraseñas de las cuentas demo (las tiene el coordinador,
  fuera del repo), por eso la ejecución 2 la hace una persona.
- La interfaz nunca ofrece franjas pasadas porque `franjas_disponibles` solo devuelve futuras; por eso la regla se prueba de verdad saltando la interfaz (consola). Quien la impone es `reservar_cita` en la base.
